# 마무리

병렬 작업자가 모두 끝난 뒤에만 실행합니다. `struct.py`는 카드 본문의 상위·다음·가지 줄을 고쳐 쓰므로 작업자가 도는 중에 돌리면 충돌합니다.

## 0. 확인
- Obsidian이 켜져 있는지 봅니다: `tasklist | grep -i obsidian`. 켜져 있으면 영진 님께 닫아 달라고 요청하고 기다립니다. 대량 작업 중 Obsidian이 파일을 덮어쓴 사고(카드 `1`)가 있었습니다.
- `git status --short | head`로 이번 세션에서 바뀐 범위를 확인합니다. 검증 작업이었다면 `영구/`에 바뀐 카드가 없어야 합니다.

## 1. 구조 갱신 (보관함 루트에서)
```
py -3 _작업/스크립트/struct.py .
py -3 _작업/스크립트/render_hub.py . _작업/구조작성/*.md
py -3 _작업/스크립트/merge_index.py .
```
- `struct.py`의 `DUPLICATE ID`, `ORPHAN` 보고와 `render_hub.py`의 `UNKNOWN ID`, `MISSING LINK` 보고를 읽고, 이번 작업이 만든 것이면 고친 뒤 다시 돌립니다.
- 원본이 없는 개요 다섯 개는 렌더링되지 않습니다(`구조작성` 스킬 참조). 카드 이름이 바뀌었으면 그 다섯 파일의 링크를 따로 확인합니다.

## 2. 전체 점검
```
py -3 _작업/스크립트/lint.py
```
- `_작업/검증/01 lint 요약.md`의 오류(E) 표가 비어 있어야 합니다. 오류가 있으면 고칩니다.
- 경고(W) 수가 작업 전보다 늘었으면 늘어난 항목을 보고합니다.
- Bash나 스크립트로 고친 파일은 훅이 점검하지 않았으므로 이 단계가 안전장치입니다.

## 3. 기록
`_작업/로그.md` 맨 아래에 `- YYYY-MM-DD 종류: 한 줄 요약`을 덧붙입니다. 종류는 `수집 · 검증 · 병합 · 연결 · 구조 · 질의 · 점검` 가운데 하나입니다. 수치(카드 수, 바뀐 수, lint 오류·경고 수)를 넣습니다.

## 4. 커밋
```
git add -A
git commit -m "<종류>: <한 줄 요약>"
```
- 커밋 메시지 접두어는 로그의 종류와 같게 씁니다.
- push는 영진 님이 요청했을 때만 합니다: `git push origin <현재 브랜치>`.
