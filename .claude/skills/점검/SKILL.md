# 점검 (주간)

카드는 고치지 않고 상태를 보고한다. 고칠 일은 보고서에 적고 영진 님께 묻는다.

## 순서 (보관함 루트, PC는 `py -3`, 클라우드는 `python3`)
1. 기준 브랜치를 받는다(CLAUDE.md '기준 브랜치'). 다른 `claude/*` 브랜치가 앞서 있으면 먼저 알린다.
2. `struct.py .` → 끊긴 링크(정상 `.txt` 4건 말고), 부모 없는 번호, 중복 번호를 본다.
3. `lint.py .` → 오류(E)는 0이어야 한다. 경고 수를 지난 점검과 비교한다(`_작업/검증/01 lint 요약.md`).
4. `queue_report.py .` → 대기열 입구(`_작업/대기열/00 대기열.md`) 갱신.
5. 아래를 세어 `_작업/점검/YYYY-MM-DD.md`에 표로 쓴다.
   - `verify`가 없는 카드(새로 만든 카드, 고친 카드): 번호 목록 → 다음 판정 묶음 후보
   - 연결 줄(상위·다음·가지 제외)이 2개 미만인 카드
   - 30일 넘게 `초안`인 카드 수(전체가 초안이면 수만)
   - 구조 노트에 나오지 않는 카드(`_작업/구조작성/*.md`의 `{번호}`에 없는 카드, 안내 카드 제외)
   - 임베딩이 낡은 카드(`_작업/검색/임베딩/*/ids.json`의 hash와 지금 본문이 다른 카드 수) → PC에서 `embed.py` 재실행 권고
6. `_작업/로그.md`에 `- YYYY-MM-DD 점검: 한 줄 요약`을 덧붙이고 `마무리` 스킬의 커밋 단계를 따른다.
