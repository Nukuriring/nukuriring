# Transparency in Complex Computational Systems

> 서지 확인 메모: 이 노트는 크릴의 논문 자체가 아니라 영진 님의 글이 소개하는 크릴의 논증을 정리한 것이다. 크릴의 문장을 직접 인용한 대목은 하나만 있으며 쪽수가 없어 카드에 옮기지 않았다.

## 한 줄 요지
크릴은 복잡한 계산 시스템에 내재한 불투명성을 해소하기 위해 투명성을 알고리즘 투명성과 구조적 투명성과 실행 투명성의 세 종류 지식으로 나누고, 실행 투명성이 독자적 범주임을 논증한다.

## 문제 설정
- 숙련되고 지식 있는 개발자와 사용자도 겪는 불투명성을 어떻게 이해할 것인가. 정보 은폐나 사용자의 이해 부족에서 생기는 불투명성은 논외이다.

## 논증 구조
1. 알고리즘 투명성(기능적 투명성)은 프로그램이 어떤 알고리즘을 예화하는지 아는 것이다.
2. 구조적 투명성은 코드가 알고리즘을 어떻게 구현하는지 아는 것이다.
3. 실행 투명성은 특정 하드웨어와 데이터 위에서 프로그램이 실행된 방식을 아는 것이다.
4. 실행 투명성의 존재 논증 1: 하드웨어나 입력 데이터와의 상호작용이 만드는 아티팩트는 알고리즘 지식이나 구조 지식으로 탐지되지 않는다.
5. 실행 투명성의 존재 논증 2: 딥드림 사례에서 엔지니어들이 얻은 지식은 기능적 투명성도 구조적 투명성도 아니다.
6. 각 유형은 다른 유형을 요구하지 않고도 드러날 수 있다.

## 핵심 개념
- 알고리즘 투명성, 구조적 투명성, 실행 투명성, 아티팩트, 독자적 범주(sui generis)
