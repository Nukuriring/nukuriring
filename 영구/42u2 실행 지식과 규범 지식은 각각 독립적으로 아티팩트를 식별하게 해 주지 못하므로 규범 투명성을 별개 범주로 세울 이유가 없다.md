# 42u2 실행 지식과 규범 지식은 각각 독립적으로 아티팩트를 식별하게 해 주지 못하므로 규범 투명성을 별개 범주로 세울 이유가 없다

지식의 유형마다 투명성이 대응한다는 지금까지의 전략을 따르면, 실행 지식에 대응하는 투명성과 정상 작동에 대한 규범 지식에 대응하는 규범 투명성을 따로 세우는 편이 개념적으로 깔끔해 보인다. 그러나 별개의 투명성을 상정하려면 각 지식의 이해가 독립적으로 아티팩트의 식별 능력을 제공해야 한다. 실행 지식의 이해가 독립적으로 이 능력을 주기 어렵다는 것은 딥드림 사례에서 확인되었다. 규범 지식의 경우도 그렇다. 이 덤벨 이미지를 분류할 때 이두를 주된 근거로 삼은 것은 비정상 작동이라는 지식이 있어도, 시스템이 왜 그렇게 작동했는지에 대한 구체적 인과적 원인은 알 수 없다. 무엇이 문제인지는 말할 수 있어도 왜 생겼고 어떻게 고쳐야 하는지는 답할 수 없다. 그러므로 실행 투명성이라는 하나의 범주를 유지하는 것이 적절하다.

- [[42u1 연구자가 실행 지식을 충분히 이해해도 아티팩트를 탐지하지 못할 수 있으므로 실행 지식의 이해는 실행 투명성의 충분조건이 아니다]]: 실행 지식의 독립적 식별 능력이 없음을 보인 논증이다.
- [[42u3a 계산 현상학의 최적의 파악과 구조적 상수와 유도 제약은 시스템의 정상 작동에 대한 규범적 지식이 무엇일 수 있는지를 구체적으로 규정한다]]: 규범 지식이 구체적으로 무엇일 수 있는지에 대한 제안이다.
- [[41q1a 크릴은 하드웨어와 입력 데이터가 만드는 아티팩트와 딥드림 사례로 실행 투명성이 독자적 범주라고 논증한다]] (반론): 실행 투명성이 독자적이라는 논증에 맞서 실행 지식과 규범 지식으로는 아티팩트를 식별하지 못해 규범 투명성을 따로 세울 이유가 없다는 점이 제기된다. (제안: Claude)
- [[41q1 크릴은 복잡한 계산 시스템의 투명성을 알고리즘 투명성과 구조적 투명성과 실행 투명성의 세 종류 지식으로 나눈다]] (반론): 영진은 실행 지식과 규범 지식이 독립적으로 아티팩트를 식별하게 하지 못하므로 규범 투명성을 별개 범주로 세울 이유가 없다고 본다. (제안: Claude)
