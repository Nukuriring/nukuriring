# 42u 크릴의 실행 투명성 정의는 실행 지식의 이해만으로 투명성이 달성된다고 보지만 정상 작동에 대한 규범적 판단이 더해져야 한다

크릴(Creel 2020)은 복잡한 계산 시스템에 대해 우리가 가질 수 있는 지식을 알고리즘에 대한 지식, 구현에 대한 지식, 특정 실행에 대한 지식으로 나누고 각각에 기능적 투명성, 구조적 투명성, 실행 투명성을 대응시킨다. 실행 투명성은 프로그램과 하드웨어, 입력 데이터, 머신 코드 번역 사이의 상호작용으로 생기는 아티팩트를 탐지하게 해 주는 투명성이다. 나는 기능적 투명성이나 구조적 투명성과 구별되는 이 특유한 범주가 있다는 데 크릴에게 동의한다. 그러나 그 범주를 특정 실행 인스턴스에 대한 지식의 획득과 결여로 규정하는 일은 부적절하다고 논증한다. 실행 투명성에는 실행 지식의 이해에 더해 시스템의 작동이 문제적이라는 규범적 판단이 필요하기 때문이다. 이는 실행 투명성이 시스템의 정상 작동에 대한 규범적 이해에 의존한다는 주장이다.

- [[42u1a 기능 지식과 구조 지식의 이해는 규범적 판단 없이 각 투명성에 충분하지만 실행 지식의 이해는 그렇지 않아서 실행 투명성이 가장 뚜렷이 구별된다]]: 기능적 투명성과 구조적 투명성과의 차이를 짚는 카드이다.
- [[41q2 실행 불투명성은 시스템이 정상 작동하는 동안에는 요점이 없고 정상 작동은 기능으로 규정되므로 그 요점은 기능적 투명성에 의존한다]]: 같은 문제의식을 초고에서 정리한 다른 묶음의 카드이다.
- [[41q1 크릴은 복잡한 계산 시스템의 투명성을 알고리즘 투명성과 구조적 투명성과 실행 투명성의 세 종류 지식으로 나눈다]]: 크릴의 세 범주를 정리한 다른 묶음의 카드이다.
- 관련 주제(다른 묶음): 실행 투명성, 규범적 이해, 아티팩트
