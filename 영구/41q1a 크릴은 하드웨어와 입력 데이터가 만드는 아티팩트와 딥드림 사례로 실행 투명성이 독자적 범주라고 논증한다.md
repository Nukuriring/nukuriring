# 41q1a 크릴은 하드웨어와 입력 데이터가 만드는 아티팩트와 딥드림 사례로 실행 투명성이 독자적 범주라고 논증한다

첫째 논증은 이렇게 진행된다. 어떤 오작동이나 아티팩트는 프로그램과 하드웨어의 상호작용이나 프로그램과 예상치 못한 입력 데이터의 상호작용에서 생긴다. 이 아티팩트는 시스템이 구현하는 알고리즘에 대한 지식으로도, 알고리즘이 구현된 구조에 대한 지식으로도 탐지되거나 설명되지 않는다. 그러므로 특정 인스턴스에서 하드웨어 상태와 입력 데이터의 특성과 둘의 상호작용을 분석하는 새로운 종류의 지식이 필요하고, 이 지식이 실행 투명성을 이룬다. 둘째 논증은 딥드림 사례를 쓴다. 엔지니어들은 시각화 도구로 모델이 덤벨을 인식하는 방식을 분석해 모델이 덤벨을 팔과 함께 나타나는 것으로 잘못 일반화했다는 새로운 지식을 얻었다. 이 지식은 기능적 투명성도 구조적 투명성도 주지 않으므로 이 둘 밖에 계산 시스템에 대한 투명성이 있고, 사용된 하드웨어와 입력 데이터를 포함해 프로그램이 실행된 방식에 대한 지식이 실행 투명성에 기여한다.

- [[41q1 크릴은 복잡한 계산 시스템의 투명성을 알고리즘 투명성과 구조적 투명성과 실행 투명성의 세 종류 지식으로 나눈다]]: 이 논증이 뒷받침하는 크릴의 세 분류이다.
- [[41q2 실행 불투명성은 시스템이 정상 작동하는 동안에는 요점이 없고 정상 작동은 기능으로 규정되므로 그 요점은 기능적 투명성에 의존한다]]: 이 논증의 전제에 물음을 던지는 영진의 논평이다.
- [[42u 크릴의 실행 투명성 정의는 실행 지식의 이해만으로 투명성이 달성된다고 보지만 정상 작동에 대한 규범적 판단이 더해져야 한다]] (다음 단계): 크릴의 독자적 범주 논증 위에서 정상 작동에 대한 규범적 판단을 더해야 한다는 보완이 나온다. (제안: Claude)
- [[42u1a 기능 지식과 구조 지식의 이해는 규범적 판단 없이 각 투명성에 충분하지만 실행 지식의 이해는 그렇지 않아서 실행 투명성이 가장 뚜렷이 구별된다]] (다음 단계): 실행 투명성이 독자적 범주라는 논증은 실행 투명성이 가장 뚜렷이 구별된다는 정리의 바탕이다. (제안: Claude)
- [[42u2 실행 지식과 규범 지식은 각각 독립적으로 아티팩트를 식별하게 해 주지 못하므로 규범 투명성을 별개 범주로 세울 이유가 없다]] (반론): 실행 투명성이 독자적이라는 논증에 맞서 실행 지식과 규범 지식으로는 아티팩트를 식별하지 못해 규범 투명성을 따로 세울 이유가 없다는 점이 제기된다. (제안: Claude)
- [[67b 실행 투명성의 달성 방법은 결여한 지식에 따라 달라지고 실행 지식과 규범적 이해가 서로 보완할 때 가장 효과적이다]] (다음 단계): 실행 투명성이 독자적 범주라는 논증은 결여한 지식에 따른 달성 방법으로 이어진다. (제안: Claude)
